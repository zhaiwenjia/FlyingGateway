# 供应商模型费率表（2026-11-13 快照）

> **本文档是费率的唯一真源**（`AGENTS.md` 规则 31）。设计文档与实现代码都从这里取数，⛔ 不在多处硬编码同一份费率。
> **币种口径**：**国内供应商一律用官方人民币原生价**（⛔ 不用美元价 × 汇率换算）；**海外供应商**官方只给美元价 ⇒ 按 **1 USD = 7 CNY**（暂定，可配置）换算。
> **精度口径**：所有单价（¥ / 1M tokens）与总费用均**四舍五入保留 4 位小数**。
> **⚠️ 费率随时会变**，本表是快照。每条带来源 URL 与快照日期。使用前务必核对官方最新定价。

## 一、币种与精度规则

| 规则 | 值 |
|---|---|
| **主币种** | 人民币（CNY） |
| **国内供应商**（DeepSeek / Kimi / 智谱 / Qwen / MiniMax / MiMo） | **官方人民币原生价**，⛔ 不用汇率换算 |
| **海外供应商**（OpenAI / Anthropic / Gemini / xAI） | 官方美元价 × **7** 换算为 CNY |
| **汇率** | 1 USD = 7 CNY（暂定，可配置） |
| **单价精度** | ¥ / 1M tokens，**保留 4 位小数** |
| **费用精度** | 各分项与总费用**四舍五入保留 4 位小数** |
| **输出字段** | `CostCNY`（主）+ `CostUSD`（参考，`CostCNY / 7`） |

⚠️ **「官方人民币价 ≠ 美元价 × 汇率」是实测事实，不是理论**：DeepSeek `deepseek-flash` 谷时输入官方 **¥1**，而美元页 `$0.15 × 7 = ¥1.05`；MiniMax `MiniMax-M3.1-Flash` 输入官方 **¥1**，美元页同为 `$0.15 × 7 = ¥1.05`；百炼 `qwen3.8-max` 国内官方 **¥12**，国际站美元价 `$2 × 7 = ¥14` ⇒ **凡国内厂商，一律以官方人民币价为准**，换算只会引入偏差并掩盖官方的定价结构。

⚠️ **全表一律以官方定价页为准**（老宅 2026-11-13 指示「费用计价以官方为准」）：国内六家取官方人民币原生价，海外四家取官方美元价 × 7 换算。**第三方聚合站（UsagePricing / LLM Cost Optimizer / PE Collective / AICalc / GetModelKey / DataLLM Lab / mimo-v2.com 等）一律不作为数据源** —— 实测其数值与官方口径存在实质不符（智谱 `glm-5`、百炼 `qwen3.8-max`、MiMo `mimo-v2-omni`、Anthropic `claude-sonnet-5` 涨价、xAI `grok-4-fast` 存在性等 5 处已实测）；取不到官方价就标「官方未列出」，⛔ 不用第三方数补。

## 三、费用计算规则

```
总费用（CNY）= 输入费用 + 缓存读取费用 + 缓存写入费用 + 输出费用

输入费用     = InputTokensUncached × 输入单价 / 1,000,000
缓存读取费用 = CacheReadTokens × 缓存命中单价 / 1,000,000
缓存写入费用 = CacheWriteTokens × 缓存写入单价 / 1,000,000
输出费用     = OutputTokens × 输出单价 / 1,000,000

总费用（USD）= 总费用（CNY）/ 7

精度：单价存 4 位小数（¥/1M tokens）；各项费用与总费用均四舍五入保留 4 位小数
     ⚠️ 先按全精度算完分项与总和，最后统一舍入一次；⛔ 不对每个分项先舍入再相加
```

**四个关键口径**：

1. **输入用 `InputTokensUncached`（未缓存新增）而非 `InputTokens`（总输入）** —— 缓存命中的部分单独按 `CacheReadTokens` 计，否则重复计费。
2. **缓存写入单独计费**（Kimi / Anthropic / Qwen / DeepSeek 都有），⛔ 不与缓存命中合并。
3. **reasoning token 计入输出**（DeepSeek / Kimi / 智谱 / Gemini 官方口径），⛔ 不单独计费但要算进 `OutputTokens`。
4. **国内供应商用官方人民币价**（⛔ 不用汇率换算），海外供应商用 `USD × 7` 换算值。

**峰谷定价（DeepSeek）**：峰时（北京时间周一至周五 9:00–12:00、14:00–18:00，排除中国法定节假日）所有单价 ×2；等价的 UTC 口径是 01:00–04:00 与 06:00–10:00。

**阶梯计费（部分 Qwen / 智谱模型）**：按**单次请求的输入 Token 总量**选档，整个请求按该档单价计，⛔ 不分段；⚠️ **输出价也随档位变**。表内 Qwen 模型均为单档。

**取消不等于免单**：智谱官方原文「客户端主动取消或断开连接后，已产生的输入和输出用量仍会正常计费」⇒ 取消路径上费用照算，⛔ 不可清零。

## 四、费用来源优先级

```
① 供应商自报费用（如 xAI 的 cost_in_usd_ticks）→ Source = ProviderReported
② 供应商返回 usage + 费率表计算 → Source = Estimated
③ usage 缺失（流中断）→ 估算 usage × 费率表 → Source = Estimated, Estimated = true
④ 费率表也没有该模型 → Source = Unknown, CostCNY = 0
```

⚠️ **`Estimated` 标志必须透传给调用方** —— 与 `Usage.Estimated` 联动：usage 是估算的 ⇒ 费用也是估算的。
