# docs/ —— 调研与结论文档

本目录放**长期引用对象**：调研报告与技术结论。

- **调研文档** —— 命名 `年月日-任务号或主题-调研-子题.md`
  （如 `20261111-路由策略-调研-负载均衡口径.md`）。一个任务一份文档，
  不是一次搜索一份。**每条结论必须带出处**（可点击 URL + 来源名 + 原话要点），
  并显式区分「来自搜索」与「我的推测」。
- **结论文档** —— 一次「定位 → 归因 → 方案 → 结果」走完就落一份，
  正文按「一、实验过程 / 二、实验发现 / 三、优化方案 / 四、优化结果」写，
  并附证据索引与复现命令。

⚠️ 文档头部写清对应的 `commit <短哈希> · PR #<号>`
（或「直推 main，无 PR」）—— 半年后要能顺着编号回到那次改动。
⚠️ 引用别人的数字**逐字复制**，不换算、不四舍五入。

`docs/images/` 放项目图等静态资源（当前是仓库图标）。
