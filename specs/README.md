# specs/ —— 需求规格

每个需求一个目录，目录名用**三位序号 + 短横线 + 主题**（如
`001-router-降级链排序`）。目录内通常放：

- `spec.md` —— 需求本身：做什么、不做什么、验收标准；
- `plan.md` —— 实施计划（若走 spec 驱动流程生成）；
- `tasks.md` —— 任务拆解（若走 spec 驱动流程生成）。

⚠️ **序号只增不改**：已存在的目录不重排、不复用编号 ⇒ 编号是需求的稳定引用。
⚠️ 需求落进 `specs/` 后，**实现进度**记在 `progress/` 的事件流里，
**技术结论**记在 `docs/` —— 三者分工见 `AGENTS.md`。
