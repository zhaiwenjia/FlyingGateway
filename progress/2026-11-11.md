## 一、做了什么

本仓从「只有 `README.md` 与 `LICENSE` 两个文件」的空仓，搭出第一版工程骨架。

**治理层**（从 `next_gen_agent_system` 仓迁移、裁剪改写而来）：

- `AGENTS.md` —— 协作规则，**裁剪改写**而非照搬：保留「铁律 / 协作与表达 /
  记录与提交 / 文档 / 版本管理 / 工作区与环境 / 重构与验证 / 调研与实验 / CI /
  代码规模」十节骨架与全部纪律内核，删掉指向 `next_gen_agent_system`
  现有代码、BFCL / harbor 实验、`.claude/skills` speckit、`outdated/` /
  `reference/` 归档目录的具体条款（那些引用在新仓全部悬空），
  另加一组**网关专属条款**（端点注册表口径、路由与降级、超时配额限流、
  凭据隔离、多端点一致性、单一数据源）。
- `.github/workflows/ci.yml` —— 两道 job：`Lint (ruff + semver)` 与

- `.github/pull_request_template.md`、`.github/CODEOWNERS`、
  `.github/BRANCH_PROTECTION.md`。

**工程配置**：

- `pyproject.toml`（uv 管理、`requires-python = ">=3.12,<3.13"`、
  `[tool.ruff.lint]` 只开 `PLW1514`、仓库级钉死 TUNA 镜像源）、
  `uv.lock`、`.python-version`（3.12）、`.gitignore`、
  `.env.example`、`bump_version.py`（SemVer 双轨制 + 组件版本快照）。

**最小可跑骨架**：

## 二、为什么这么做

- **AGENTS.md 裁剪改写，不照搬** —— 源文件 299 行 / 30 条款，其中大量条款
  直接点名 `next_gen_agent_system` 的具体文件（`src/core/agent/budget.py`、
  `src/core/memory/memory_store.py`）、具体实验（BFCL 子集、harbor 队列）
  与具体目录（`outdated/`、`reference/`、`.claude/skills/`）。
  照搬过来，这些引用在新仓**一个都不存在** ⇒ 规则会指向空气，
  且新仓的真实问题没人管。
  ⇒ 做法：**保留纪律内核，替换项目特有处，再补网关自己的条款**。
  内核（禁止 mock / 占位、证据与复核、edge case 即修、双轨 SemVer、
  本地绿 ≠ CI 绿、调研三动作、1000 / 600 行两档）跨项目通用，照搬即可；
  项目特有处按新仓形态重写。

- **骨架里写的是真代码，不是占位** —— 源仓铁律 1 明令「禁止 mock / stub /
  占位」。一个只会 `pass` 的空包配上一条绿的 CI，等于用「测试通过」掩盖
  「什么都没做」。
  ⇒ 做法：三个模块各司其职且**真能跑**（注册表真的拒绝重名、路由真的给
  降级链、配置真的在字段非法时抛错），CLI 真的能打印一次路由决策。

- **本仓暂不引入 HTTP 客户端** —— 网关当前实现的是「决定发给谁」，
  那部分是纯逻辑。引一个 HTTP 库会让依赖从 0 变成 N，而**还没有任何代码
  需要发请求**（源仓规则 6：除非必要，不引入新依赖）。
  ⇒ 决定：**先把路由决策与配置口径做扎实**，HTTP 那一层作为下一轮 spec。
  ⇒ 因此 `.env.example` 里目前**没有凭据键位** —— 写上不存在的键位，
  等于文档与实况不符（源仓铁律 2）。

- **CI 不带 `push` 触发器** —— 沿用源仓口径：PR 合并走 squash 会产生新 SHA，
  GitHub 当成一次全新提交，同一份代码在 PR 里验过一遍、squash 后又跑一遍，
  纯浪费 Actions 分钟。

- **`test/` 必须带 `__init__.py`** —— 实测踩到：`unittest discover -t . -s test`
  要求起始目录**可导入**，没有 `__init__.py` 直接报
  `ImportError: Start directory is not importable`，一条测试都跑不起来。
  源仓的 `test/` 也有这个文件。

## 三、从过程和结果中学到了什么

- **`unittest discover` 的 `-s test` 不是「指个目录就行」** —— 它要求该目录
  **可导入**。⇒ 凡是「目录里全是测试文件」的新仓，`test/__init__.py` 是
  **必需品**，不是可选项。这条在源仓的 AGENTS.md 里没写（源仓有那个文件，
  但没说为什么），踩到时只看到一句 ImportError。

- **ruff format 会改我写的代码** —— 我按 88 列手排的换行，`ruff format`
  在 preview 模式下有自己的偏好（多行参数列表的收拢方式）。
  ⇒ 与其手猜格式，不如**先写再 `ruff format` 让它定稿**，
  然后 `ruff format --check` 自然过。⚠️ 注意 `preview = true` 开着时
  格式化行为与稳定版**可能不同** ⇒ CI 与本地必须**同一个 ruff 版本**
  （都从 `uv.lock` 装，别一个用全局一个用仓内）。

- **`ruff` 没装在全局 PATH 里** —— 本机只有 `uv`，`ruff` 是 `uv sync` 装进
  `.venv` 的。⇒ 门禁命令必须写成 `uv run ruff ...`，直接敲 `ruff` 会
  「command not found」。这正是源仓那条「先补 PATH 再跑全量」的同款情形，
  只不过这次的解法更干净：**用 `uv run`**，不依赖 PATH。
