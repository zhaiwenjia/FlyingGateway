**为什么这么做**：仓库实现方向定为 Go，约束（规则 / CI / 版本机制）必须与代码同栈，否则「规则说 A、工具查 B」——照规则写的人被 CI 打回。版本走 git tag + ldflags 是因为「版本只有一个真值」：`__version__` 双轨制在换栈后没有对应物，git tag 天然是单真值；ldflags 注入点用 `internal/version` 包承载，未注入时 "dev" 不会被误当发布版本。删除 Python 骨架（约 950 行）而非留作参考，是因为两套栈并存只会让约束继续分裂；历史在 git 里可取回。

**从过程和结果中学到了什么**：
① **「命令找不到」先查 PATH 与常见位置，再下「没装」结论**：本会话连续两次命中（`go`、`gh` 都在 `/opt/homebrew/bin` 但不在默认 PATH）——`which` 空 ≠ 没装，`ls /opt/homebrew/bin/<cmd>` 一条就见分晓；规则 19 的「不在默认 PATH 就等于没装」是**排查起点**不是结论。
② **`gh pr merge --delete-branch` 会顺手清理本地分支与 worktree**：随后的 `git worktree remove` / `git branch -D` 报「not found / not a working tree」**不是失败**，是清理已完成 ⇒ 判定以 `git worktree list` 与 `git ls-remote --heads` 为准，别把「已经是目标状态」的报错当故障重试。
③ **git rm 只删跟踪文件，未跟踪缓存（`__pycache__`）不受影响**：worktree 里删掉 tracked 的 .py 后，主工作区合并完仍残留未跟踪的 `src/` `test/` 空壳（内含 `__pycache__`）⇒ 换栈这类「删一批文件」的改动，收尾要查 `git status` 的未跟踪残留。
④ **python3 heredoc 写中文 progress 偶发 Non-UTF-8 报错**（本会话两次）⇒ 稳妥路径是 write 工具落临时文件再 `cat >>` 追加，零编码问题。
