## 2026-11-13 16:45:13.737 汇率由 1:6.7 调整为 1:7，费率表全量重算

**做了什么**：① 老宅改口径「1 USD = 7 CNY」，费率表 `docs/20261113-供应商模型费率表.md` 里 **158 处 USD→CNY 换算全部重算**（151 处 `$X → ¥Y` 正向 + 7 处 `¥Y（$X）` 反向，如 GLM 表）；② Go 设计文档 §7.2 的汇率口径同步改 7 处（§7.2 引用行、§7.2.1 `CostUSD` 说明、§7.2.2 公式、§7.2.6 表格与说明）；③ 顺带修 §7.2.5 里 3 处上一轮被 shell 反引号展开吞掉的反引号内容（`AGENTS.md`、`cost_in_usd_ticks`、`config/rates.json`）；④ 记 progress。

**为什么这么做**：汇率是**所有 USD 供应商费率的换算基准** ⇒ 改一个数会让整张表的 158 个 CNY 值同时失真，必须全量重算而不是只改汇率文字。CNY 官方价的行（Kimi 全部、GLM 官方价、Qwen 官方档位、MiMo 国内版）**不参与换算**，脚本按「同行出现 `$` 才算换算对」处理，实测这些行一字未动。

**从过程和结果中学到了什么**：
① **改汇率前先证明「原表用的是哪条换算规则」**：先写校验脚本确认原表 158 个值**全部**满足「`USD × 6.7` 按各值自身小数位四舍五入」（不匹配 0 处）⇒ 才敢用同一规则重算到 7 ⇒ 重算后再跑一遍校验（158/158 一致）。没有这一步就是「凭感觉改数字」，改完无法自证。
② **整数汇率比小数汇率更干净**：6.7 会让 `0.15` 变成 `1.005`（3 位小数），7.0 下 `0.15×7 = 1.05`（2 位）⇒ **重算后表里的小数位普遍收敛**，可读性变好，不是副作用是巧合的收益。
③ **批量重算文档数字要写成脚本、且要留双向校验**：正则必须区分两种排版（`$X → **¥Y**` 与 `**¥Y**（$X）`），漏一种就会留下半张表用旧汇率、且**肉眼极难发现**（数字看着都合理）⇒ 校验脚本按同一批正则回读并断言 `值 == USD × 7`，不靠肉眼扫。
④ ⚠️ **heredoc 不加引号定界符 = 反引号被 shell 执行**（本轮第 3 次踩）：`cat >> file << EOF` 中写 `` `AGENTS.md` `` 会被当命令跑并吞掉内容 ⇒ 本轮用 `python3 - << 'PYEOF'`（**引号定界**）写长文本才是安全姿势。
